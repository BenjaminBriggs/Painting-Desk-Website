# Painting Desk Website — Spec

The marketing and support site for **Painting Desk**, the miniature-painting tracker for iPhone and
iPad, at **paintingdesk.app** (app repo: `../Plinth`). The app was called Plinth until 2026-10-02
(§11.1); the code, the bundle ID and the repo folders keep that name, and nothing a visitor sees does.
Built on the same stack as `../Magic-Sudoku-Website`, so anything learned there applies here.

Status: pages, drawn screens, legal copy, icons and og image done. Name and domain decided (§11.1); blocked on §11.2–3. Last updated 2026-10-02.

Defaults that can be overridden rather than rediscovered are marked **[D]**.

---

## 1. Purpose

1. Make the App Store listing look like a real product: a home for the app, its screenshots and
   what makes it different.
2. Host the pages App Review needs before the app can ship: **support URL** and **privacy policy
   URL** (plus **terms** if the app sells anything — see §11).
3. Give shared links somewhere to land, if the app ever shares links rather than images.

Not a blog, not a community, not tutorials (the app's own non-goals, `../Plinth/docs/SPEC.md` §11).

## 2. Audience

Miniature painters: wargaming, historicals, RPG figures, busts, scale models. Mostly arriving from
the App Store, search, or a share. They know the hobby's vocabulary (sprue, primed, layer, glaze);
the site should speak it without explaining it.

## 3. Pages (v1)

| Path | Purpose | Must contain |
|---|---|---|
| `/` | Landing | Name, one-line pitch, App Store button (release switch, §6.4), the eight store boards as sections (the Showcase is the hero; each other board gets a drawn screen, §5.1), the no-account / no-server privacy pitch, a closing call to action |
| `/support` | App Review support URL | Contact email, FAQ, how to report a bug |
| `/privacy` | App Review privacy URL | What is stored (on device and in the user's iCloud), what is not (no server, no account, no analytics), contact |
| `/terms` | Only if the app is paid or has purchases (§11) | Licence (Apple standard EULA), purchase/subscription terms, refunds via Apple |
| `/404` | Unknown paths | Way back home; `noindex` |

Later, only if needed: a press kit (`/press`: icon, screenshots, one-paragraph description,
contact), release notes.

## 4. Content

**Source of truth for copy and images is the app repo, not this site:**

- Store order and captions: `../Plinth/docs/APP-STORE.md`. The landing page's sections follow the
  iPhone board order and use the same small uppercase line + headline pairs:
  Showcase "Every model deserves a plinth", The Desk "Finish what's on the desk",
  Sprue to Done "Every stage, photographed", Paint Rack "Know every pot you own",
  Colour "Build the perfect recipe", Recipes "Repeat any paint job",
  Painting Clock "Know where every evening went", Stats "See what you finish".
  Two departures since the rename (2026-10-02, Ben's call): the hero's headline is "Finish what's on
  the desk", so the Shelf-and-Desk section is headed "A shelf for the pile. A desk for the work.";
  "Every model deserves a plinth" left with the old name. The App Store Showcase caption in
  `APP-STORE.md` still carries it and wants the same look.
- Screenshots: `../Plinth/docs/Screenshots/en-US/<iPhone|iPad>/` (generated by `Tools/screenshots.sh`).
  Export for the web as WebP, 2× the displayed size, ≤ 250 KB each.
- App Store name / subtitle: "Painting Desk: Mini Tracker" / "Paint inventory & colour tools"
  (app SPEC §10.6; the name is 27 of the 30 characters allowed). The page `<title>` uses the same name.

**Rules:**

- **No Games Workshop marks** anywhere on the site, in copy, alt text, keywords or file names (one
  deliberate exception: the hero iPhone's demo-store screens, §5.2) —
  no "Warhammer", "40k", "Citadel", "Age of Sigmar". Same IP position as the app (app SPEC §10.6,
  §11). Generic terms reach the same people: miniature, wargaming, tabletop, RPG, scale model.
  This includes screenshots: check no paint names in a shot are a GW product name before using it.
- Spelling: British (**colour**) **[D]** — the app's own copy and docs use it.
- No emoji. No full-page gradient washes. No highlighter/marker effects on headlines.
  (Ben's call on the Magic Sudoku site; same taste here.)
- Status is never colour alone (the app's rule, DESIGN.md): every accent-coloured thing has a word.

## 5. Design

The app's "Studio" direction — a neutral grey ground, ink, one accent, serif for names, sans for
reading. The palette is Sanzo Wada's combination 303 (chosen 2026-10-03, replacing warm paper and
oxblood): slate-olive ink, peach red for the one action, neutral-grey plinths, Naples yellow for
highlights. Tokens come from `../Plinth/docs/DESIGN.md`; this table is the subset the site uses.

| Token | Hex | Use on the site |
|---|---|---|
| `paper` | `#F3F2F0` | Page background |
| `card` | `#FAFAF9` | Cards |
| `soft` | `#E0E0DC` | The pegboard behind the desk and the rack; the glass behind a pot's paint |
| `track` | `#DAD9D5` | The stage selector's track |
| `border` | `#D4D3CF` | Card edges |
| `rule` | `#CCCBC7` | Dividers, the header's bottom edge |
| `plinth` | `#B6BFC1` | The strip under every photo, secondary button borders, the shelf rail |
| `faint` | `#AEADAB` | Disabled text |
| `muted` | `#4B5445` | Secondary text, uppercase labels |
| `ink` | `#1C251A` | Text, selected states, the text on the App Store button |
| `accent` | `#B74424` | Accent text: small uppercase lines, days, warnings. Peach red deepened to read at 4.5:1 |
| `accentFill` | `#F15A30` | **One** action per screen, the App Store button: true peach red with ink on it (4.7:1), lightening on hover |
| `accentTint` | `#FBE6A0` | Naples yellow, rare highlights |

- **Type:** Instrument Serif (Google Fonts) for anything that names something — headlines, section
  titles, feature names. System sans (`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`)
  for everything you read. Uppercase micro-labels: 12px, tracking 0.15em, `muted`.
- **Shape:** DESIGN.md's, not a web template's. Cards radius 6, one `border`, no shadow; buttons
  radius 8 (primary accent, secondary `card` with a `plinth` border); pills only for chips and the
  selector. Titles hang from a 1px `ink` rule. The header is the app's navigation bar: paper, the
  serif name, a `rule` along the bottom — no floating glass.
- **Text on accent** is white (`onAccent #FFFFFF`).
- **Dark mode:** not in v1 **[D]**. DESIGN.md has the dark ladder if it's wanted later.

### 5.1 Drawn screens

The landing page shows each store board as a screen drawn in HTML from the app's own components,
not a screenshot: the shelf, the desk and the Showcase as one flow (the backlog on plain paper, the
desk on the pegboard, the moves between them in the app's words), the stage selector and photo prompt, the paint
rack (pots on rails, `images/pots.svg`), the colour ramp, a recipe, the painting clock, stats. They
stay light on paper, carry no third-party marks, and cost a few KB.

- **Pots** come from the app's artwork (`../Plinth/Plinth/Assets.xcassets/PaintPots`: the
  Generic, ArmyPainter, AK, S75 and Pot shapes, never the GW-named one), composed as `PaintSwatch`
  does: the silhouette in `soft`, the paint's hex over it clipped to its level, the cap, the
  overlay at 25%. Shape and cap colour follow `PotShape.swift`.
- **Paint names and hexes are real** and come from the app's catalogue, never Citadel. The ramp is
  `ColourEngine.ramp` from Vallejo Orange Rust (default settings) over the catalogue without
  Citadel: every step within ΔE 1.1. Recompute it before changing a paint or a number.
- Kits, dates and stats are illustrative, with generic names (no GW units).
- **The colour section is live** (`js/colour-tool.js`): six preset pots, any colour from a picker,
  or a tap on the hero photo (a 15px patch averaged, never one pixel); ramp with a hue-shift slider,
  and the four harmonies. It ports `ColourEngine` (OKLab, ramp, harmony, ΔE × 100, close < 2,
  near < 5) and matches against `data/paints.json`, built by `python3 tools/paints.py` from the app's
  catalogue: solid finishes only, no Citadel, no licensed ranges (D&D), no mediums or primers, no
  names that are a GW mark or SS. Rerun it when the catalogue changes; it prints the paint count the
  section's footnote quotes.
- **The hero is the app with pieces of it set around it** (after Flighty's), the app first and
  "Finish what's on the desk" centred under it, then the iPhone in the middle cycling the app's screens (§5.2), the model's stages
  to its left with a desk card, and the ramp, a running clock and a "Last pot" card to its right.
  The cards hold still; only the phone and the model's stages move. Sized in em, so one font size
  per breakpoint scales it; from 1024px that size comes from the window's height, so the headline
  and the App Store button still make the first screen. Below 640px it is the model and the phone alone.
- **The hero is one model at every stage**: `images/stages/<stage>.webp`, cropped to 9:16 by
  `python3 tools/stages.py` from the camera originals in `images/models/` (git-ignored, 404 on the
  site). The finished photo loads with the page; the other four load after it, play through once,
  and the stage row under the photo shows any of them on a tap. Check each crop for GW text before
  shipping: the sprue's frame has "Warhammer" moulded on it, which its crop leaves out. Alt text and
  file names say "miniature", never the unit.
- **Motion** says something or isn't there: the headline set down on its plinth (CSS), the hero's
  stages played Sprue to Done, pots filling to their level, stats bars growing, the clock
  running. All of it is off under `prefers-reduced-motion`, and the page is drawn finished first.

### 5.2 The app on iPhone

The hero's iPhone (a drawn frame at the centre of the hero) shows the app's
own screens in turn: Desk, Kit, Paint Rack, Colour, Showcase, Shelf (`images/screens/*.webp`,
420px wide, 2× the frame). They are light-mode captures of the app's **demo store**, so they carry
its Games Workshop kit names, "Warhammer 40,000" tags and Citadel paints. That is a deliberate
exception to §4, Ben's call on 2026-10-02: the phone shows the app as it really is. It ends when
the demo store is made GW-free (§11.5), and the captures should be retaken then.

To retake them, on a throwaway simulator (never the one you work on):

```
UDID=$(xcrun simctl create "Painting Desk Web Capture" com.apple.CoreSimulator.SimDeviceType.iPhone-17-Pro-Max com.apple.CoreSimulator.SimRuntime.iOS-27-0)
xcrun simctl boot $UDID && xcrun simctl bootstatus $UDID -b
xcrun simctl install $UDID <DerivedData>/Build/Products/Debug-iphonesimulator/Plinth.app
xcrun simctl ui $UDID appearance light
xcrun simctl status_bar $UDID override --time "9:41" --wifiBars 3 --cellularBars 4 --batteryState charged --batteryLevel 100
# one launch per screen, a screenshot after it settles (about 9 s):
#   --demo --tab desk                                   desk
#   --demo --tab desk --screen kit/subductor-squad      kit
#   --demo --tab paints -rackLayout grid                paints
#   --demo --tab paints --screen colour/citadel.layer.ushabti-bone   colour
#   --demo --tab showcase                               showcase
#   --demo --tab desk --screen shelf                    shelf
xcrun simctl launch --terminate-running-process $UDID pro.briggs.plinth <arguments>
xcrun simctl io $UDID screenshot <screen>.png
cwebp -q 80 -resize 420 0 -metadata none <screen>.png -o images/screens/<screen>.webp
xcrun simctl shutdown $UDID && xcrun simctl delete $UDID
```

## 6. Stack and conventions

Same as `../Magic-Sudoku-Website` (see its `CLAUDE.md`). No build step: edit HTML/CSS/JS directly.

| Piece | How |
|---|---|
| Styling | Tailwind via CDN (`cdn.tailwindcss.com`) + the theme in `js/tailwind-theme.js`; component classes (buttons, glass, labels) in `css/site.css` |
| Fonts | Google Fonts: Instrument Serif; system sans |
| Header / footer | Client-side includes: `<span include-html="/includes/header.html">`, loaded by `js/includes.js`, which fires `includes-loaded` when done |
| JS | Vanilla, one file per concern in `js/` |
| Hosting | Netlify, publishing the repo root; config in `netlify.toml` only (no `_redirects` — one source of truth) |

### 6.1 Every page

- `<title>`, meta description, canonical URL, Open Graph + Twitter card tags, favicon set.
- The header include, `<main>`, the footer include, then `js/includes.js` and `js/app-store.js`.
- Loads `js/tailwind-theme.js` straight after the Tailwind CDN script, then `css/site.css`.

### 6.2 URLs

Extensionless links (`/support`, `/privacy`) **[D]** — Netlify serves `support.html` for
`/support`. Canonical tags use the same extensionless form. Check each with `netlify dev` before
relying on it.

### 6.3 Hiding repo files

Netlify publishes the repo root, so `netlify.toml` 404s `SPEC.md`, `CLAUDE.md`, `/tools/*`, `/images/models/*` and `/docs/*`. Add
any new non-site folder to that list. Keep design sources (Affinity files, raw screenshots) out of
the repo entirely.

### 6.4 App Store release switch

`js/app-store.js`, copied from Magic Sudoku. `const APP_RELEASED = false;` turns every
`apps.apple.com` link into a disabled "Coming soon to the App Store" label (the header's says
"Coming soon"), and swaps any element's text that carries `data-coming-soon="…"`. Launch day: set it
to `true` and push. The App Store URL is a placeholder until the app has an ID (§11).

### 6.5 Images

WebP, explicit `width`/`height`, `loading="lazy"` below the fold. Budget: landing page ≤ 1.5 MB on
first load.

## 8. Local development

```
netlify dev --dir . --port 8888
```

`netlify dev` (not `python3 -m http.server`) so the `netlify.toml` redirects and headers apply
locally. The includes use `fetch()`, so `file://` won't work.

Running more than one of these sites at once: `netlify dev` always starts its internal static
server on port 3999, so the second one fails with `EADDRINUSE`. Give each site its own pair:

| Site | Command |
|---|---|
| Magic Sudoku | `netlify dev --dir . --port 8888` |
| Painting Desk | `netlify dev --dir . --port 8890 --staticServerPort 4001` |
| Portfolio | `netlify dev --dir . --port 8892 --staticServerPort 4003` |

## 9. Verification before every deploy

What caught real bugs on Magic Sudoku:

1. Screenshot every changed page at 1440, 390 and 375 px wide (headless Chromium — the
   Playwright-cached `chrome-headless-shell` works without installing anything) and look at them.
   The header is the usual casualty at 375.
2. Crawl every internal link and `#anchor` against `netlify dev`; all 200, all anchors exist.
3. No console errors on any page.
4. Release switch in both states: no live `apps.apple.com` links while unreleased; all links back
   when released.
5. `/support` and `/privacy` load — App Review taps them.

## 10. Deployment and git

**Git:** GitHub repo `painting-desk-website` (private until launch **[D]**; not created yet).

- `main` = production. Netlify deploys every push to `main`.
- `dev` = work branch. Merge to `main` by PR when ready to ship.
- Commit before switching branches; never switch with uncommitted work.
- `.gitignore`: `.netlify`, `.DS_Store`, editor lock files.

**Netlify (one-time):**

1. `netlify init` from this folder (or "Add new site → Import from Git" in the dashboard), linked to
   the GitHub repo.
2. Build command: none. Publish directory: `.` (repo root; pinned by `[build] publish` in `netlify.toml`). Production branch: `main`.
3. Branch deploys for `dev` **[D]**, so every push has a preview URL.
4. Add the custom domain `paintingdesk.app` (§11.1), let Netlify provision HTTPS, redirect `www` → apex.
   `.app` is HTTPS-only (HSTS-preloaded for the whole TLD), so nothing on it works over plain HTTP.

**Before the domain is live,** the Netlify subdomain (`<site>.netlify.app`) can serve as the
support and privacy URLs in App Store Connect — but those URLs are baked into the listing, so set
the real domain first if at all possible.

## 11. Open decisions

Ordered by what they block.

1. ~~**Domain.**~~ **Resolved 2026-10-02: Painting Desk, at paintingdesk.app.** The app was renamed
   from Plinth because Plinth B.V. ships "Plinth – 3D Scanner for Art" on the App Store, with a
   Sculpture Mode for figurines: the same name, the same store and an adjacent use. Every usable
   Plinth domain was taken too (plinth.com, plinth.app, plinthapp.com, plinth-app.com and more).
   Still to do, both Ben's: **register paintingdesk.app** (unregistered when checked, standard
   price), and **search UKIPO and EUIPO for "Painting Desk" in class 9** before launch. The name is
   descriptive, so a clash is unlikely, but so is registering it as a trade mark.
   paintingdesk.com is parked for sale on Sedo; not needed for launch.
2. **Free vs paid** (app SPEC §12.2). Decides whether `/terms` exists and what it says, and the
   "price" line on the landing page.
3. **App Store ID.** Needed for the App Store links, the Smart App Banner
   (`<meta name="apple-itunes-app" content="app-id=…">`) and launch.
4. **Universal links.** Only if the app will share links (it shares images today). If yes: add
   `applinks:paintingdesk.app` to the app's associated domains and serve
   `/.well-known/apple-app-site-association` here as `application/json` (the header rule is already
   in `netlify.toml`). Bundle ID `pro.briggs.plinth`.
5. **Screenshots ready for the web.** No longer blocks the site: the landing page draws its screens
   (§5.1). It still blocks the App Store listing.
   Every capture in `../Plinth/docs/Screenshots/en-US/iPhone/` (checked 2026-10-02) shows GW
   marks: "Warhammer 40,000" in the kit's tags, Citadel ranges and paint names on the rack, colour,
   recipe and stats shots, and GW unit names on the desk, kit and clock. That breaks §4 here and
   app SPEC §10.6 for the App Store set itself. Fix in the app's demo seed (`PlinthKit/Sources/PlinthDemo`)
   and recapture.
6. **Analytics:** none **[D]**. Keeps the privacy page true to "no tracking". If ever added, it must
   be cookieless and named in the privacy policy.
